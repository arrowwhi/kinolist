# 2. Контент рилсов — через сторонний скрапер

Дата: 2026-08-18
Статус: принято

## Контекст

Основной сценарий начинается со ссылки на рилс Instagram. Публичного API для
чтения чужих постов не существует: Graph API отдаёт только контент аккаунтов,
которыми владеет приложение.

Остаются три пути:

1. Свой HTTP-клиент к публичной странице. Бесплатно, но Instagram отдаёт
   login wall на большинство анонимных запросов и банит IP датацентров.
   Работоспособность требует резидентных прокси либо залогиненной сессии —
   последнее нарушает условия использования и рискует аккаунтом.
2. Сторонний скрапер (Apify, обёртки на RapidAPI). Платно, зависимость от
   вендора, но стабильность и легальность — его забота.
3. Не поддерживать ссылки вовсе.

## Решение

Используем сторонний скрапер за портом `enrichment.ReelFetcher`. Адаптер
`repository/instagram` тонкий и читает несколько вариантов имён полей: обёртки
регулярно их переименовывают.

Порт имеет метод `Enabled()`. Без ключа сервис поднимается и работает —
ссылки отклоняются понятной ошибкой, добавление по названию доступно.

Любой отказ разбора ссылки ведёт к сообщению «пришлите название текстом».

## Последствия

Положительные:

- Самая хрупкая часть системы изолирована одним файлом; смена вендора не
  затрагивает домен, usecase и транспорт.
- Сценарий не заходит в тупик: у пользователя всегда есть рабочий путь.
- Отсутствие ключа — не отказ сервиса, а деградация функции.

Отрицательные:

- Постоянные расходы, пропорциональные числу присланных ссылок.
- Внешний сервис может измениться или закрыться. Смягчено толщиной адаптера и
  фолбэком на ручной ввод.
